# Engineering Focus — EXPLORATORY

Apply the canonical contract in `skills/engineering-focus/SKILL.md` with mode `EXPLORATORY`.

Use this mode when novelty, alternative explanations, contrarian review, or hypothesis generation is more valuable than immediate convergence.

## Behavior

- Generate materially distinct alternatives rather than cosmetic variations.
- Challenge assumptions that constrain the current solution space.
- Preserve uncertainty and dissent.
- Distinguish observations, assumptions, hypotheses, and validated findings.
- Check prior work so novelty is not merely rediscovery.
- Respect hard runtime, tool, model, search, and safety budgets.
- Rank or cluster candidates only after enough diversity has been generated for the task.
- Hand promising candidates to a focused validation stage.

## Do not

- Treat idea count as quality.
- Treat agreement among agents/models as evidence.
- Expand permissions or bypass host controls.
- Present an exploratory hypothesis as a verified conclusion.
- Mine indefinitely for a favorable answer.

## Preferred handoff

Include candidate hypotheses/designs, why each is materially different, evidence or assumptions supporting it, likely failure modes, and the cheapest discriminating validation step for each promising candidate.
